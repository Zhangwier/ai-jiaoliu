## 01. 成品目标、交付形态与编辑原则

### 1.1 作品真正要让观众获得什么

演讲结束后，普通观众能够说出并操作三件事：
1. 选配置：模型、客户端/工具、设置、权限与成本共同决定任务表现；不靠单一榜单。
2. 交任务：写清目标、输入来源、约束、允许拒答与验收标准；不要先把结论塞给 AI。
3. 验交付：打开实际文件、看源文/原图、复算关键数字；可区分“好看”“完整”“可用”“可信”。

把整个正文写成一条悬念链：**惊艳输出 → 可靠性怀疑 → 看清技术机制 → 对比真实交付 → 建立检查方法 → 再回看同一任务**。抽象理论不得连续出现过多而不回到具体例子。

### 1.2 两种明确分开的成品

- **现场演讲版**：建议 35–45 分钟，正文约 32–42 个实际放映页（含展开/过渡页；真实数量随排练调整），另保留隐藏互动辅助页。原稿 1–67 的核心内容须覆盖，压缩的是屏幕同步阅读量，不是科学事实和实证细节。可以另保留 50–60 分钟深讲版本，但需独立标注。
- **资料完整版**：保留并继续完善成品48全量 154 页、备注、来源、企业档案、实验解释及附录；不强求这套资料连续讲完。最终应交付“适合投屏的演讲版”和“完整可审查的参考版”，双方互相链接。

未取得用户对真实时长的进一步约束时，先按 40 分钟排练档设计，不应假设“越短越好”。若某案例是本次分享重点，优先加给它时间而非平均分配到榜单和术语。

### 1.3 页面信息分层（必须落实）

- **观众屏幕层**：一句有结论的标题＋一个被展示的对象＋至多三处当前讲解焦点。短句不是硬性字数标准，公式、原文证据允许完整展示在可读的局部放大框内。
- **讲者备注层**：为什么、怎么算、例外、口播、争议边界、素材出处和点击提示。不能因为屏幕减字就删除原始论证。
- **会后资料层**：完整模型列表、数字来源、成本口径、引用清单、工程参数明细、复算步骤与版权说明。
- **严谨底线层**：来源、日期、样本量、定义和方法边界仍在对应页可定位的位置出现；不要把“本地单次实验”漂白为通用科学结论。

## 03. 视觉总规范：不是换模板，而是换表达介质

### 3.1 每个内容先选“最适合证明它的视觉”

| 内容类型 | 首选载体 | 少用的载体 |
| --- | --- | --- |
| 顺序/推理生成 | 分步图解、每次点击拼接的 token、轻量代码动画 | 大段“定义+特点+结论” |
| 内部因果/信息流 | 状态图、数据流、重点路径逐帧亮起 | 纯箭头旁堆段落 |
| 结果对比 | 原件与模型输出局部放大，先猜后揭晓 | 十列表同时满屏 |
| 原文错误定位 | 原图裁切、同坐标标注、单位/条款高亮 | 只看结论的表格 |
| 大数字/研究结果 | 一组数值＋分母/场景＋解释边界 | 不带范围的巨大百分数 |
| 产品选型 | 分场景决策树、成本/权限关口、可替代路径 | 广告式 12 宫格与单一“王者推荐” |
| 方法升级 | 固定任务逐级增加验收装置，右侧“检查覆盖”动态变化 | 不断追加小字条目 |
| 附录检索 | 导航卡、可点击目录、资料索引 | 现场逐页朗读大量文字 |

### 3.2 画面与字幕约束

- 正文保持已有深蓝/暖白主题，青绿色表示可靠行动/链接，橙色表示“待核/风险/反例”，不要把橙色用成任何强调的万能色。
- 一张屏幕讲**一个主判断**；确需显示长原文时，只裁切会影响论证的 1–3 行，同时保留“看全文/页码”链接与附录。
- 现场正文主要显示字建议 24–32pt；核心数字和结论 34–52pt；解释图签 17–22pt；来源 11–13pt 只作溯源而非现场要读的说明。这个比例是本稿设计目标，不是权威硬标准。务必投屏模拟 6–10 米/教室后排验证。
- 文本改写坚持“结论式标题＋图下证据”；少用绕口成语、长串产品简称。英文名必需时一次讲清中文用途。
- 表格只用来显示“需要对照的少量数据”；整表可保留于资料版，现场版用聚焦行/列动画；对原始数值不可因美观任意取整或重新归一化。
- 页面间动画默认无；仅同一物体需要跨页变形/位置变化时 Morph。普通进入动画统一淡入/擦除，强调优先高亮/遮罩，低价值弹跳飞入全部禁用。
- 除非用户专门要求电影化开场，一律不用持续全屏粒子、无意义背景循环、AI 生成的长篇氛围视频。动画应解释事实、过程或变化。
- 逐步显示时，隐藏的答案不可从缩略图/备注/可访问内容误泄露；同时必须有静态模式、键盘可回退和音频失效回退。
- 原稿正文页脚“来源索引”在48版必须指向重建的48版索引；避免“附录原来页号”因裁减而失效。

### 3.3 动画规范与素材策略

- 低成本：PowerPoint 原生出现/淡入、擦除、字体颜色、形状/遮罩、区域高亮、触发器。
- 中成本：复制相邻幻灯片＋Morph（物体位置/状态平滑变化）；勿在大量表格上期待 Morph 生成正确数字过渡。
- 高成本：可控 HTML/SVG/Canvas/Manim 动画先制作，再输出 1080p 或 1440p H.264 MP4 嵌入 PPT；保留可编辑文字叠层与静态首尾帧。适合 token 分布、注意力、信息干扰、RAG 信息流、聊天改口时间轴。
- 视频必须离线可播，音量/字幕/循环/开始触发清晰；不可只保存在线地址，素材版权可查；6–15 秒的解释微动画往往比 60 秒炫片更有用。
- 一页原则上 2–5 次动作；超过 6 次需评估拆页或以视频自动演示。**动作点击数不是体验质量指标**；为真实揭晓节奏可以例外。
- 每个动态页提供一张无动画静态示意；即便播放插件不工作，也能用鼠标/键盘讲清同一结论。

### 4.1 本次优先制作的 12 处“演示标志场景”

**最高优先 8 处**：13 token 生成、17 长上下文、22 十宫格、39–40 A/B竞猜与揭晓、49–50 聊天改口、54 升级路线、58 RAG、65 闭环收束。其余第二批：08 拟合、12 奖励黑客、16 注意力、23 模型与外壳、42 假错误核验、45 原文错误放大、63 多Agent协作。第一批中 39/40、49/50 视为一个双页场景。

**明确定义成功效果**：观众仅看画面，能叙述出“是什么改变了结果”；不是“动画完成率100%”。动态视频不必占满屏幕；信息多且需要对照时，PPT原生对象常比视频好控制。

## 05. 三个可直接交给制作人的关键分镜脚本

### A. 第13页「模型是怎样一步步写出答案」

- 初始帧：画面只有提问“什么是工程量清单？”和右侧一条空白回复栏；屏幕不要在开始就出现完整流程解释。
- 第1击（0–3秒）：模型收到当前输入，箭头指向候选 token 区域；出现 3–5 个候选词及“概率是示意数据”小标签。
- 第2击（3–6秒）：一个候选被圈选移动到回答末尾；其余候选淡出。
- 第3–4击（6–12秒）：重复两次，逐步得到一句通顺但仍未核证的话；短暂停顿。
- 第5击（12–16秒）：在下方出现“流畅≠核验”并列红色疑问号。讲者强调“内部复杂计算与外部查证不是一回事”。
- 开发选择：优先用 SVG/HTML 程序动画生成离线 MP4，放入原生 PPT；做可点击静态分帧作为保险；字幕及概念文本仍用 PPT 原生元素确保清晰。

### B. 第39–40页「先投票，再拆穿‘看起来努力’」

- 39首帧：左右 A/B，仅有“耗时 29分40秒/3分03秒”“提交 26条/11条”等实验记录，标题不含暗示答案。讲者发问“你敢用哪份？”
- 39停顿：真实现场让大家举手或口头选择（无网络也可参与）；除 A/B之外的条件一致与否由讲者备注交代，不制造严格对照的假象。
- 40第1帧：只显示K1/K2两个符号，不直接整表。先点 B 两个绿标。
- 40第2帧：展示 A 的 8 条已核假错误，给一条可放大的原图证据；再补“另21条待核”。
- 40第3帧：十组完整表作为最后核对/附录入口，标题是“列得多，不等于找得准”，不是“谁是最强模型”。
- 技术：原生形状动画＋原图裁切触发器。**所有数字取自现有复核口径**，若两/三检查点版本冲突，必须先按48当前的 K1/K2统一。

### C. 第49–51页「没有新证据，为什么改口？」

- 49：只展示第一轮判断核心理由，且确认它在该特定几何假设下成立；不给出最终改口结论。
- 50第1击：用户反驳（逐字内容依真实截图，必要时做工作场合温和提示；不可捏造对话）；右上出现“新增可核证证据：0”。
- 50第2击：13秒来自记录时则做独立计时提示，否则只标“短暂停顿”；不刻意伪造真实等待时长。
- 50第3击：模型的立场方向从“坚持条件”移至“同意用户”，同步标出推理/证据并未增加。
- 51：先出现“研究中，有用户反驳时的谄媚表现更多”，第二拍再出 18% 与 9%，第三拍明确**个人指导对话样本、相关非因果**；最后落到操作：“要求新证据、重算、允许保留有依据的不同意见”。
- 技术：聊天回放首选PPT遮罩/逐项淡入；若要视频，加入暂停点；不能仅为效果剪去关键模型原话。

## 07. 外部范本：具体学习什么、不照搬什么

### 7.1 权威科普及教学

1. 3Blue1Brown《Large Language Models Explained Briefly》（2024-11-20）：https://www.3blue1brown.com/lessons/mini-llm/ 。学习“先给具体字符串→一步一步推导 token 概念→抽象机制”；供13/16等页。
2. 3Blue1Brown《Attention in Transformers, Step-by-Step》（2024）：https://www.3blue1brown.com/lessons/attention/ 。学习词的语境变更、关系连线与逐次更新；不必移植全部三维数学效果。
3. Andrej Karpathy《Deep Dive into LLMs like ChatGPT》（2025-02-05）：https://www.youtube.com/watch?v=7xTGNNLPyMI 。学习预训练、tokenization、模型输入输出、后训练与使用方式分层；适合纠正7–19的表述和附录历史。
4. Fiorella & Mayer, Cambridge Handbook of Multimedia Learning（2021章节）：https://www.cambridge.org/core/books/abs/cambridge-handbook-of-multimedia-learning/principles-for-reducing-extraneous-processing-in-multimedia-learning/F29A19FCD34C542806F736E0661C05F5 。学习排除无关内容、强调信号、空间/时间邻接；不把“加了动画”当自动提高记忆率。
5. OpenAI、Thinking Machines、Chroma、Anthropic 的前述原始研究分别用于 13–18、49–51 页；科学口径以原文结果和适用样本为准。

### 7.2 GitHub 与工具 Skill（按本项目实际收益排序）

1. PPTAgent/PPTEval：https://github.com/icip-cas/PPTAgent 。参考其内容、视觉、连贯性三维评估与**先分析参考稿再逐页修订**流程，反对从原始长文一键重做整个PPT。
2. Slidev 动画：https://github.com/slidevjs/slidev/blob/main/docs/guide/animations.md 。学习分步揭示与点击驱动的演示理念；不是要求把 Office 项目迁到网页。

6. PowerPoint 动画与切换差别：https://support.microsoft.com/en-us/powerpoint/the-difference-between-animations-and-transitions 。先区分控制对象、触发时机和退场行为，避免把“添加动画”当作通用解法。
