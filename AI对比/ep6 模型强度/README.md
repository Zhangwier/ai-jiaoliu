## 这一轮补的八件东西（2026-10-22）

1. **一张三向全表**：OpenAI 官方 gpt-oss model card（arXiv:2508.10925）同一个档位参数在 19 个评测上跑完，给出三种形状 —— 15 行单调升（AIME 2025 120b 50.4/80.0/**92.5**）、3 行中档最优（Tau-Bench Airline 20b 32.0/**42.6**/38.0）、1 行两尺寸单调降（HealthBench Consensus 120b 90.6/**90.8**/89.9、20b 84.9/83.0/82.6）。**这是"档位效果取决于任务形状，不是模型属性"最难反驳的一手证据**，且由厂商自己发布。

   从这张表能直接推出四条：① **低→中的边际远大于中→高**（AIME 2025 20b：+35.0 然后 +19.6）；② **档位买得到推理，买不到知识**（AIME +54.6，MMLU 只 +4.9）；③ **工具与思考预算部分可替代**（AIME 带工具后档位收益变小，HLE 带工具后反而翻倍）；④ **小模型吃档位吃得更多**（AIME 2025 20b +54.6 vs 120b +42.1）—— 档位是小模型最便宜的变强手段。

   还有一条官方原话，讲清了这些东西的物理实现：**"These levels are configured in the system prompt by inserting keywords such as 'Reasoning: low'."** 档位在 gpt-oss 上就是系统提示词里的一句话，不是采样参数。
2. **一句话定性**：arXiv:2605.16938 的标题就是结论 —— **Effort as Ceiling, Not Dial**（是天花板，不是旋钮）。操纵检查证明 effort 参数只设"生成上限"，不驱动实时分配，分配策略训练时就定型了。比 Anthropic 的 "behavioral signal, not a strict token budget" 更硬。
3. **一个方法论警告**：arXiv:2610.10049 实测 GPT-5.1 三档思考 token **116 / 118 / 118** —— 请求里写的档位和实际烧的 token 可以完全脱钩。**所以本项目配置名里的 "high" 证明不了它真的 high**，要回看响应里的 `reasoning_tokens`。这条直接影响 ep1 结论的边界。
4. **一对双刃**：Fu et al.（arXiv:2602.08874）低档 safe rate 仅 7%、失败构成里 Harm-ID-Failure 占 **72.7%**（没识别出意图，不是过度拒答）；Zhao et al.（arXiv:2509.06861）高档让幻觉涨 15%~25%。**低档漏识别，高档多编造，中间那段才是安全区。**
5. **一个正在发生的活案例**：Claude Code 2026 年 2–4 月的档位被悄悄调低（[issue #42796](https://github.com/anthropics/claude-code/issues/42796)）。AMD 的 Stella Laurenzo 用 6,852 个 session、17,871 个 thinking block、234,760 次工具调用做反向审计，把"我感觉它变笨了"变成了带时间戳的表格：**Read:Edit 从 6.6 掉到 2.0**（编辑前不读文件的比例 6.2% → 33.7%）、"simplest"一词出现率 **+133%**、提前收工/甩锅话术从 **0 次变 173 次**、用户打断率涨 **12 倍**。三处变更全部没进 release notes：上线 adaptive thinking、**默认档位从 high 调到 medium**、thinking 内容停止回传。成本反噬更狠 —— 3 月 API 请求涨 **80 倍**、折算 **$42,121/月**，而实付 **$400/月**。**这一条把本文所有论断从"实验室结论"变成"已经发生过的事"。**
6. **客户端层摸清了四家**：ChatGPT 的档位是 **Instant / Medium / High / Extra High / Pro**，其中**前四档都是 GPT-6 Sol，只有 Pro 换成 GPT-6 Astra** —— 拨到最后一格时模型也换人了；Claude 是模型菜单里的 Effort 菜单；Qwen 是 Thinking 开关 + effort；Grok 是 Auto / Fast / Expert / Heavy。还有一条反直觉：**在 ChatGPT 里打字说"think harder"不会改变档位**，必须在选择器里点。另有一份 Artificial Analysis 的五档扫描把边际收益衰减量化了：GPT-6.1 Sol 从 low 到 medium 涨 **6 分**只多 **$0.08**，从 xhigh 到 max 涨 **1 分**要多 **$0.33**。
7. **厂商文档自己打架的七处**（汇编 1.1 节 + 台账 #38）：Gemini 默认档（thinking.md 说 Gemini 3 默认 high，逐模型表却给 4-argon / 3.8-flash / 3.6-flash 默认 medium）；Gemini 2.5 用哪个参数（Interactions 页与 legacy 页相反）；OpenAI Astra 默认档全文未披露；Anthropic「Not every model that supports max supports xhigh」不给清单；智谱 GLM-5.3 同页先给 none/minimal→low 映射又写「仅 max/high/low，其余报错」；混元新旧页不一致；xAI 同一参数在 multi-agent 上控的是 agent 数量（4 或 16）不是思考深度。**这一节本身就是可讲的内容：连厂商都写不清楚，用户当然分不清。**
8. **两件别人已经做完的事，直接可用**：① **Reasoning Dial**（Kaggle 预注册，60 题 × 4 模型 × 4 档 × 2 重复，1,800+ 次调用，代码公开）—— 12 个「模型 × 任务」组合里 **7 个准确率无变化**、成本涨 1.5–3.4×，唯一显著提升是 gpt-5.4-mini 逻辑题 15% → 97.5%，输出 token 最高涨 **14.08×**。**这是全篇唯一能被别人原样重跑的数字。** ② **鹈鹕测试榜**（tihu.app，linux.do 用户 sonnemusk，54 个「模型 × 档位」组合，同一句鹈鹕提示词）—— **和我们 ep1 的鹈鹕测法是同一件事，只是别人把档位也扫了**：Claude Opus 5.5 medium 7.89 > high 7.86（升档反降还更慢），Grok 4.7 medium 5.82/21.6s → xhigh 5.99/**582.9s**（27 倍时间换 0.17 分）。**这一条直接补上 ep1 缺的那一维。**

## 与 ep1–ep5 的关系

- ep1–ep4 测"交付物像不像样"，ep5 测"被质疑时守不守得住"，ep6 测的是**这些结论在什么设置下成立**——它是前面五集的**前置条件检查**，不是第六个对比实验。
- 直接后果：ep1 十个配置里至少两个把档位写进了名字（E = hy4 preview 1M **high** workbuddy，G = gpt 6.1 sol **high** codex），其余八个档位未记录。**"某模型比某模型强"这条结论，成立范围应写成"在各自客户端默认档位下"。**
- 与成品46 的接口：P65（B1c 降智）与 P99–P101（E1 降智测试）讲的是**同档位下的质量变化**；本 ep 讲的是**档位本身被改**。两者体感一样、成因不同，叠加起来就是"今天特别笨"。若后续进 PPT，最自然的挂点是 P65 附近（给"降智"加一条并列成因）或第 02 章模型与工具。
- 与 P12（温度 0 跑 1000 次得 80 种回答）的接口：思考模式下温度可能被静默忽略（DeepSeek 官方明说"不报错但无效"），所以 P12 在推理模型上可能有另一个解释 —— 这条列为待核。
